# Guia de Contribuição

Agradecemos seu interesse em contribuir para este projeto!

Este documento fornece diretrizes para contribuir de forma clara, eficiente e padronizada.

---

## 💡 Como Contribuir

1. **Fork** o repositório e crie sua branch:

   ```bash
   git checkout -b nome-da-sua-feature
   ```

2. **Implemente** sua melhoria ou correção com mensagens de commit claras e objetivas.

3. **Garanta que os testes e automações funcionem** (se aplicável).

4. **Abra um Pull Request (PR)** com uma descrição concisa do que foi feito.

---

## 🧪 Tipos de Contribuição

* Correções de bugs
* Melhorias de performance ou organização de código
* Adição ou correção na documentação (`README`, `SECURITY`, etc.)
* Traduções e correções de ortografia

---

## 🧱 Convenções de Código

* Mantenha a padronização já existente (identação com 4 espaços,  docstrings).
* Nomeie funções e variáveis de forma clara.
* Prefira `with` ao lidar com arquivos.
* Use try/except com tratamento útil e mensagens compreensíveis.

---

## 📂 Organização Recomendada

* **`main.py`**: ponto de execução principal
* Documentação em `docs/`
* Logo do projeto em `docs/logo/`
---

## ✅ Checklist para Pull Request

* [ ] O código foi testado localmente
* [ ] Foram criadas ou adaptadas docstrings e comentários relevantes
* [ ] A estrutura de pastas foi respeitada
* [ ] O comportamento existente não foi quebrado

---

## 📫 Contato

Para dúvidas, envie uma issue ou mensagem direta no canal de comunicação indicado no repositório.

Obrigado por ajudar a melhorar este projeto! 🙌
